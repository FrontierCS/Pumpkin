Wait for a run to end and say how it ended.

While the run goes on, `wait` says each of its milestones on the standard error. Once the run has
ended, `wait` says its summary and the command that runs it again. Ending `wait` doesn't stop the
run, but `pumpkin cancel` does.

With `[controller]` in the configuration and no `--runs`, `wait` follows the run on the controller.
It then copies the record into the default runs directory.

Usage: pumpkin wait [OPTIONS] <run>

Arguments:
  <run>
          The run's id, a prefix of the id or of its last 8 digits that no other run shares, or its
          record's path with a `/`

Options:
      --runs <dir>
          The directory to look the run up in (default: `runs` in the repository's `.pumpkin`)

      --outcome
          Print the run's outcome.json on the standard output once it ends, even if it failed to
          start

  -h, --help
          Print help

Examples:
  pumpkin wait 20261108-000905-126a21e9
  pumpkin wait 126a
  pumpkin wait runs/20261108-000905-126a21e9
  pumpkin wait --outcome 126a > outcome.json

Exit status:
  0  The run finished with a result.
  1  The run failed, was interrupted or was lost, or another error.
  3  The run finished without a result.
